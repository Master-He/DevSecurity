# DAST 引擎 SPEC

## 1. 目的

对已部署、已授权的 Web 应用和 API 进行黑盒测试，从外部观察输入、响应、会话和配置，发现认证、访问控制、注入、SSRF、安全配置等问题。

DAST 与源码扫描的最大区别是会产生真实网络请求，因此“授权目标管理”是一等功能，不是扫描器的可选项。

## 2. 范围

MVP：

- Web 应用基线扫描和 API 扫描；
- 已登记目标、环境、维护窗口、允许的域名/IP/CIDR；
- 认证配置的安全保存与短期注入；
- OpenAPI/Swagger 作为 API 输入；
- 结果标准化、证据脱敏、复验和误报处置；
- 与 SCA/SAST 结果按项目聚合。

后续：

- 认证状态录制与更细粒度的多角色测试；
- GraphQL、WebSocket 和复杂业务流；
- 发现问题后的复测和回归门禁。

非目标：

- 扫描未登记的公网或云服务；
- 绕过速率限制、WAF 或授权范围进行攻击；
- 自动修改或利用生产数据；
- 把“请求成功”直接当作漏洞确认。

## 3. 授权与目标模型

每个 `ScanTarget` 至少包含：

- 组织/项目、环境名称、目标 URL；
- 允许的 host、IP/CIDR、端口和协议；
- 归属负责人、安全审批人、有效期；
- 允许的扫描级别、维护窗口和速率上限；
- 是否存在测试账号、是否允许写操作；
- 禁止路径和敏感接口；
- 授权证明引用和审计状态。

创建扫描时必须进行以下检查：

1. 用户拥有项目和扫描目标权限；
2. 目标当前有效、未过期、处于允许环境；
3. DNS 解析结果和重定向目标仍在允许范围内；
4. 代理/出口只能访问白名单；
5. 禁止云元数据地址、管理网段和内部扫描器控制面。

目标由 DNS 动态解析时，扫描运行期还要重新校验。任何重定向到范围外都终止该请求并记录诊断。

## 4. 扫描模式

- **Baseline**：对现有页面和 OpenAPI 描述进行低侵入检查，默认 MVP。
- **API**：基于 OpenAPI、GraphQL schema 或接口清单爬取和测试。
- **Full**：主动爬虫、主动注入和更多检查；需明确授权和维护窗口。
- **Authenticated**：使用短期测试账号和会话，多角色权限测试作为后续能力。
- **Re-test**：只复验指定 Finding，不允许无限制扩大到新路径。

默认禁止危险写操作、文件上传、批量删除和大规模并发。任何主动扫描必须在策略中明确允许。

## 5. 功能需求

### 5.1 输入

- 目标登记信息与扫描 profile；
- URL、OpenAPI 文档、认证方式；
- 扫描窗口、并发、请求速率和最大时长；
- 允许/排除路径；
- 可选 seed URL 和测试数据说明。

凭据由平台 Secret Store 引用，运行时短时注入；结果、日志、请求和报告中不得回显 Cookie、Authorization、密码或 token。

### 5.2 爬取与探测

- 尊重 robots；测试环境的 robots 不能覆盖用户授权范围。
- 不跟随范围外链接、第三方脚本和未授权下载。
- 对 API 操作区分只读和写操作；写操作必须显式允许。
- 限制请求数、响应大小、并发和扫描时长。
- 发现登录、验证码、MFA 或速率限制时停止相关探测并报告阻塞原因。
- 支持暂停、取消和紧急停止；取消后所有新的目标请求停止。

### 5.3 检测规则

首版建议以 OWASP ZAP 的稳定扫描集为基线，覆盖：

- 安全响应头/TLS/跨域配置；
- 常见 XSS、SQL 注入、路径穿越、命令相关输入；
- 开放重定向、SSRF 候选、敏感信息暴露；
- 认证/会话配置；
- API schema 与错误处理风险；
- 组件指纹仅作为线索，不替代 SCA。

每条规则需有独立 ID、风险说明、CWE/OWASP 映射、请求证据和复现条件。

### 5.4 证据与确认

- 保存脱敏后的请求/响应摘要、时间、规则 ID 和 payload 类别。
- 高风险发现需要二次验证或人工确认；扫描器单次命中的置信度必须可见。
- 对于时间型或状态型漏洞，证据应包含对照请求和可重复步骤，不只依赖提示文本。
- 去重指纹由规则、规范化 URL 路径、参数、认证上下文和根因构成；查询参数随机值不能产生大量重复。

## 6. 引擎策略

首版候选为 OWASP ZAP，通过 API 或命令行适配器运行。选择理由：开源、API 丰富、支持 OpenAPI 和传统爬虫。上线前仍需验证：

- 商业内网使用许可；
- 主动/被动扫描效果；
- 认证和脚本扩展的安全性；
- 内存和扫描时长；
- 报告结构和可复现性。

备选为 Nuclei 模板化检测，但模板安全、版本更新和目标范围控制需另行评估。任何模板不得执行任意命令或读取 Runner 文件。

## 7. 输出与接入

- 统一 Finding（必须标记确认状态和证据可见性）；
- 引擎原始 JSON/HTML 报告存对象存储；
- 扫描摘要：请求数、错误数、目标范围、耗时、停止原因；
- 目标健康状态和授权失败诊断。

API 不得因扫描请求而暴露任意 URL 的网络可达性。创建扫描时只返回登记目标和授权错误，不返回内部解析地址。

## 8. 安全与非功能需求

- 出口代理默认白名单，阻止 DNS rebinding、重定向逃逸和跳转协议；
- 平台控制面不能被目标访问；
- 凭据只对单个任务可见，任务结束立即失效；
- 扫描流量有独立限速和配额，避免压垮测试系统；
- 默认最大并发和持续时间可配置，超时强制终止；
- 日志不包含完整认证头和敏感响应体；
- 扫描器插件/脚本必须签名、审核并锁定版本。

## 9. 测试与验收

- 使用本地靶场验证已知 Web/API 漏洞；
- 使用范围外 URL 验证请求被代理阻断；
- 验证重定向、IPv6、DNS rebinding 和云元数据地址不能逃逸；
- 扫描取消后不再发起目标请求；
- Cookie/token 不出现在日志和标准化结果；
- 超时、授权失败、目标不可达、认证失败能被准确区分；
- 误报样本和重复 URL 能正确聚合。

## 10. 里程碑

1. 确认目标和授权模型，搭建本地靶场。
2. 完成 ZAP Baseline 适配和证据脱敏。
3. 加入 OpenAPI 和受控主动扫描。
4. 完成范围逃逸与凭据泄漏测试。
5. 小范围测试环境试点后再考虑全量模式。

本阶段不实现扫描代码。
