# 设计说明

## 设计目标

DevSecurity 的界面首先服务于两类高频场景：研发判断“这是不是我的问题、怎么修”，以及安全团队判断“影响范围多大、是否要阻断发布”。界面应强调风险上下文和行动路径，不用复杂图表掩盖数据缺失。

## 核心体验原则

1. **结论可解释**：任何高风险都展示来源、位置、置信度和证据；不允许只有分数。
2. **状态真实**：扫描失败、部分成功、数据陈旧、未授权和“无发现”必须分开。
3. **操作可逆**：取消扫描、撤销抑制、重新打开问题、卸载 Agent 都有清晰路径。
4. **高风险少打扰**：结果支持去重、负责人和期限，但不通过隐藏低风险制造虚假安全感。
5. **最小暴露**：默认展示修复所需信息，不展示源码全文、Cookie 或令牌。

## 页面骨架

- 左侧：项目选择、主导航、当前组织。
- 顶部：项目/环境上下文、全局搜索、通知、身份和帮助。
- 主内容：页面标题、范围与统计窗口、主要行动、数据表/详情。
- 详情采用“摘要 + 证据 + 历史”的分栏结构，保持风险定位与修复上下文同屏。

## 状态视觉

- 严重性：critical/high/medium/low/info，文字标签和形状共同表达。
- 置信度：confirmed/high/medium/low，避免和严重性混为一色。
- 扫描：queued/running/succeeded/partially_succeeded/failed/canceled/expired。
- 数据时效：正常、陈旧、同步失败；陈旧数据不能显示为绿色“安全”。

## 文案

- 使用“发现问题”“未发现已知问题”“扫描未完成”三种明确说法。
- “误报”必须经过复核流程；“接受风险”必须有到期时间。
- 错误提示包含下一步，例如“目标未授权，请安全负责人登记目标”，而不仅是内部错误码。

## 设计交付

实现阶段需提供：

- 设计 token 和组件清单；
- 概览、风险列表、Finding 详情、扫描创建、Agent/target 管理和审计页面；
- 1024px、1280px、1440px 关键断点；
- 空、加载、错误、无权限、过期和部分失败状态；
- 可访问性检查记录。
