# 扫描任务工作流

## 创建

创建请求必须说明扫描类型、项目、代码/target、profile、请求来源和幂等键。平台验证：

- 当前用户/服务账户是否有 `scan:create`；
- 项目配额是否可用；
- 代码 revision 或目标是否有效；
- 扫描类型与输入、profile 是否兼容；
- 高危 DAST/IAST 操作是否满足授权与环境约束。

## 状态

| 状态 | 含义 | 用户可见 |
|---|---|---|
| queued | 已接收，等待 Runner/资源 | 队列位置或等待原因 |
| provisioning | 准备输入、授权或运行环境 | 当前阶段 |
| running | 引擎已启动 | 最近进度和心跳 |
| finalizing | 上传、去重、聚合、清理 | 收尾状态 |
| succeeded | 所有必需步骤完成 | 结果完整性说明 |
| partially_succeeded | 至少一个步骤失败但有可用结果 | 缺失范围和诊断 |
| failed | 未产生可信的完整结果 | 稳定错误码和下一步 |
| canceled | 用户或策略取消 | 是否已清理、部分结果是否可用 |
| expired | 超时/租约/保留过期 | 过期原因 |

## 错误呈现

用户看到“失败原因 + 可操作下一步 + 请求 ID”，例如：

- `SOURCE_REVISION_NOT_FOUND`：检查分支/commit；
- `TARGET_NOT_AUTHORIZED`：联系安全负责人登记目标；
- `RUNNER_TIMEOUT`：检查项目规模或申请专项 profile；
- `DATA_SNAPSHOT_STALE`：结果标为部分完整；
- `ENGINE_UNAVAILABLE`：可重试，不能当作零发现。

## 取消和重试

- 取消是异步操作，页面显示停止进度；已结束任务不可取消。
- 取消必须终止子进程、停止网络请求并清理临时输入。
- 重试创建新 attempt，不覆盖历史结果。
- 资源不足或引擎故障可有限重试；输入错误需修复输入后手动重试。

## 验收

- 重复提交同一 `Idempotency-Key` 返回同一任务。
- 同一任务不能进入相互矛盾的状态。
- Worker 崩溃后任务在租约过期后被安全恢复，不出现两个同时有效执行者。
- 部分成功详情明确哪些检查未运行。
- 取消后经超时仍能看到清理结果或清理失败告警。
