# 首次使用与接入

## 用户故事

作为 DevOps 工程师，我希望将一个已有仓库接入流水线，在每次合并请求时启动代码扫描，并在构建中根据项目策略获得明确结论。

作为研发人员，我希望看到本次变更引入的问题、直接依赖风险和修复建议，而不需要阅读多种扫描器原始报告。

## 首次流程

1. 首版管理员使用部署脚本生成的本地账号密码登录；OIDC/团队自动映射作为后续接入。
2. 创建项目，选择代码源：受控 Git 集成或安全上传。
3. 选择语言/profile，创建第一个扫描。
4. 平台校验项目权限、代码 revision、配额和配置。
5. 任务进入队列，页面展示真实状态和数据保留提示。
6. 扫描结束后展示结果摘要、失败诊断或明确“未发现已知问题”。
7. DevOps 创建服务令牌并接入 CI；令牌只展示一次。
8. CI 使用 `Idempotency-Key` 创建扫描，轮询或接收 Webhook。

## 验收场景

- 无效或不在允许列表的仓库被明确拒绝。
- 代码源不可访问、revision 不存在、文件过大、归档不安全时均有可操作错误。
- 项目成员和权限可以通过 SSO 映射，不要求手工创建每个用户。
- 首次扫描即使耗时，页面仍显示心跳和最后进度。
- 扫描失败不会展示“0 个漏洞”或绿色安全结论。
- 用户删除项目和平台按策略过期清理时，行为符合已确认的数据保留规则。

## 非目标

- 首次配置不需要用户理解每个扫描器命令行参数。
- 不以默认全仓库扫描一个巨大 monorepo 代替明确的子项目配置。
- 不在接入流程中自动安装 IAST Agent 或创建 DAST 目标。
