# 产品判断

## 主要用户

**应用研发**

需要快速知道问题是否与自己代码、依赖或测试环境有关，获得可执行修复建议，并能够申请误报/风险接受。

**安全工程师**

需要配置扫描和策略，理解风险分布与趋势，处理高置信度问题，发现扫描或数据源失效，管理例外。

**DevOps/平台工程师**

需要通过稳定 API、CI 插件、Webhook 和 SARIF 接入，而不是维护每个扫描器的原生脚本。

**部门负责人**

需要看到项目级风险、修复进度、阻断原因和资源消耗，避免只得到一个无法解释的总分。

## 核心价值

1. 用统一入口减少安全工具碎片化；
2. 让发现结果能追溯到证据和负责人；
3. 把安全能力嵌入已有流程，减少手工工作；
4. 在结果不完整或权限不足时保持诚实；
5. 帮助组织逐步形成可度量的安全门禁。

## 产品取舍

- 优先做项目级可操作性，不先做跨组织大屏。
- 优先支持主语言和主代码平台，不用“支持几十种语言”的宣传替代真实覆盖。
- 首版以集成成熟开源引擎为主，避免自研多语言分析器拖慢闭环。
- 默认异步扫描和警告式门禁；阻断策略需要明确负责人和审计。
- 风险分数是排序工具，不是漏洞事实；详情页必须能解释输入。

## 衡量方式

- 从创建扫描到研发看到结果的时间；
- 扫描成功率和失败原因分布；
- 高置信度问题修复/复核周期；
- 误报/接受风险比例及其到期情况；
- CI 集成后的手工操作减少量；
- 数据快照滞后和引擎版本漂移；
- 用户不需要阅读原始扫描器报告即可处理问题的比例。

所有指标在有基线后设定目标，防止为了数字隐藏问题。
